## Newly exposed problems, ranked for the release handoff

All diagnoses below are [ESTABLISHED: source] unless separately labelled as an observation or inference. Rankings and fixes are [ASSUMED]. These are additions to the existing S9 queue, not claims that all were observed in an unaided five-minute trial.

1. **The departure target omits its conditions and uses a different speed frame from FLIGHT.** MISSION and MAP show only `DEPART 50 M/S` (`src/content/gravity-range/briefing.ts:91`, `src/console/pages/MissionPage.tsx:50`, `src/console/chart.ts:68`). Actual judgment occurs beyond **9,000 km from the binary barycentre**, needs **50 m/s relative to it**, and currently caps **total spent Δv at 16 m/s** (`briefing.ts:33`; `src/game/objectives.ts:49`, `:148`). FLIGHT's unqualified Speed is relative to Alpha (`src/console/FlightHud.tsx:57`). A judge can exceed 50 on that gauge without satisfying departure, and exploratory burns consume an undisclosed cap. **2F + integrator:** implement the already approved A18 assist/excluded-learning-burn rule; supply a believed-side progress/reason summary if absent. **2D:** disclose conditions and reference frames, and distinguish reached/missed/insufficient measurement. About 80–160 UI lines plus 2F's already scoped objective change; no responsible new estimate for that game change here. Prove threshold/frame cases, a learning burn followed by a valid assist, a plain-burn non-assist and a missed departure with an understandable reason. Never read truth directly for UI progress.


2. **MISSION estimates the wrong recorder power at selectable rates.** `src/console/pages/MissionPage.tsx:41` uses 0.1/1 Hz as the 15/35 W breakpoints; `data/ship-baseline.json` and `src/ship/sensors/index.ts:41` use 1/10 Hz. The draft therefore predicts about 17 W at 0.2 Hz and 35 W at 1 Hz, while actual requested draw is 15 W for both. At 10 Hz actual requested draw is 35 W, but acquisition is bounded by the one-second game tick. These are distinct effects: 0.05 to 0.2 Hz can acquire more packets at the same power, and 1 to 10 Hz can spend more power without ten times the records. **2D + ship/sensors owner (3C for sensors):** derive preview from the same public nominal ratings, label requested versus delivered cadence, and reconcile unsupported rate choices; roughly 30–70 UI lines, sensor cadence work separately scoped if desired. Model/contracts need no new hidden information. Verify all four selectable rates against actual powered telemetry and recorded timestamps.
