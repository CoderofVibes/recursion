[ESTABLISHED: `src/model/forecast.ts:408`, `:504`, `:711`; `src/model/settings.ts`] Forecast samples are normally spaced by **60 ship s**. The output stops before the first sample whose longest **1σ position axis exceeds 10% of the distance to the nearest body**, or whose predicted position is nonfinite; its horizon is the time of the last retained sample. The model's 12 h default duration applies only when the request omits duration; the game supplies its requested span. There is no fixed 10 h or 601-sample cap in this path. For an issue at T+0, 601 inclusive samples at 60 s spacing end at T+10 h, so such an output is compatible with an earlier horizon inside a 48 h request. The exact reason for an individual cutoff requires its sample diagnostics; the visible horizon alone establishes only how far that forecast speaks. Read the actual **ENDS** and **ISSUED** times for every capture, and never present the requested span as assured coverage.
