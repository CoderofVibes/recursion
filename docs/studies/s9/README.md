# S9 — the first five minutes

Design review, 2026-11-14 Pacific. Recommendation only; the owner decides through the integrator. No application source changes.

**Recommendation:** make preparation, elapsed time and retained evidence legible before adding more instruction. Preserve the player's draft, expose the existing view shortcuts, show why warp returned to 1×, and lead from a retained debrief to an independent test. Keep the actual maneuver, TEST and ADOPT as player decisions. **The present default-1× route does not deliver the complete idea in five minutes.** A default burn starts after 400 seconds; the useful observation arcs are hours long. Higher warp can compress those arcs, but discoverability, model work and repeated alert stops still need a fresh human trial.

## Shortest route and a five-minute target

[ASSUMED] Skip optional MAP, SHIP, procedure saving and A/B overlay management for this first insight. Prepare a player-selected burn, commit before leaving PLAN, ENTER, choose warp, observe and finish; collect a separate observation; TEST on a held-out attempt; ADOPT; issue a fresh forecast and compare it with fresh motion. [Timing evidence](timing-evidence.md) counts the logical actions, including Escape when leaving CONSOLE, and distinguishes this known-protocol route from a proven global minimum. Recording intent and previewing are useful but add actions; a lucky unexplained collision is not an instructional shortcut.

[ESTABLISHED: timing sources] The prior two-eight-hour-dive plus third 15,000-second protocol requires **20 h 10 min at 1×**, before reading and model work. Its ideal arithmetic at 2000× is 36.3 seconds; that excludes all throughput limits, warning stops, navigation, model fits and reasoning. It cannot be advertised as a 36-second demonstration.

[ASSUMED] Target 285 seconds, leaving 15 seconds contingency: 30 entry/orientation; 45 first planning; 45 first observation/debrief; 60 second planning/observation/return; 45 evidence/test/adoption; 60 new-flight verification. The budget is a **hypothesis** for a human trial after R1–R8, not a result. The stronger version adds keyboard completion (R9–R14), readable numerical evidence, and a first-flight comparison centered on the observed interval. A smaller version of R1–R7 removes major confusion but loses a clearly verified final payoff; shortcuts and captions alone cannot guarantee a five-minute science loop.

If the budget still fails, the integrator should request a newly validated evidence protocol from 2F/2G, using sensed moving objects or closer useful observation geometry while preserving A10/P4/P11. That needs encounter/estimator verification. It is not permission for 2D to prefill secretly correct burns, synthesize observations, suggest the correct rule unasked, auto-adopt or accelerate through warnings. A4's fallback where the model suggests a candidate remains a separate owner choice.

## What building this takes

Budget roughly **450–850 production lines** across independent changes, allowing shared implementation; each request carries its own estimate and acceptance evidence. R9–R14 add focus/key handling in `RoomView.ts`, shared primitives, ship/map panels and evidence alternatives. Do not sum overlapping estimates as a fixed quote.

**Model:** no new estimator or hidden-state data for the core recommendations. Existing outcomes, issued forecasts, extension tests, calibrated distances and diagnostics are sufficient. Keep current gate/fit semantics. **Contracts/data:** no required shared-contract change for R1–R14; future multi-region keyboard picks use charted data only. If measured samples/last covered time cannot be derived accurately from existing records, request an explicit believed-side summary from the game owner rather than reading truth.

This conflicts with the stated no-pause goal. 2F/2G must reconcile command epoch and continued simulation; 2D must not hide it by merely changing copy. The known model-fault fix, real hands-on response, rock ranging and Beta exit belong to their existing owners. A future shorter encounter/evidence protocol is also a content/model task, not a cosmetic timer change.

Acceptance: complete the per-request checks, then observe at least five fresh desktop players [ASSUMED sample size] at 1× entry with manual warp, no developer console or supplied burn recipe. Record page-load→first plan→first retained evidence→test→adoption→fresh observed agreement times, stalls and input method. Ask each to identify which data were held out and whether the original forecast changed. A five-minute pass requires their explanation and observed agreement, not merely clicking ADOPT. Include the no-loss Recall route and a failed test; repeat on the integrated inclined range.
