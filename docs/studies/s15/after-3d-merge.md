# S15 — checks after 2G's 3D merge

[ASSUMED] These are acceptance requests for the integrator and the named owners. S15's measured baseline predates the 3D physics/model merge; its timing values are not a release certificate for that merge.

1. **Integrator: capture a new baseline before merging optimizations.** Record the new commit, `src`/`data` tree hashes and every emitted file hash. Run the same command, Chrome, viewport, DPR, 4× CPU and 10/1 Mbit/s + 40 ms profile, five cold/warm load pairs and the entire 72-trial matrix. Keep the pre-merge vectors. Compare like-for-like fixture and profile, and retain individual trials as well as pooled quantiles. Never substitute dev-server timings or repeatedly load the public deployment.
2. **2G: verify the known model fault is actually gone.** The S15 source snapshot can produce `luDecompose: singular matrix`; the existing fix is `ab7801a`. Check short arcs, early refresh, an empty archive, one usable plus one unusable attempt, model-worker initialization and rejected calls. Then repeat the benchmark with a healthy model. A failed/refusing estimator can look cheaper; do not call that a performance improvement. Also re-run the two completed dive/held-out/adoption path with bounded records; S9's very long second arc is a separate archive stress case, not a successful adoption reference.
3. **2G: remeasure real simulation work in three dimensions.** Retain the same physical step, laws, recorder rates and seed. Record top-warp request, saturation fraction, actual ship seconds per wall second, and time spent in `stepShipSystems`, power/thermal dispatch, geometry/mass properties, gravity integration, sensing and collision detection. Include inclined bodies/rocks and yaw/pitch/roll-hold activity. Recheck the 10 ms budget, eight-tick check cadence and app's 100 ms wall-delta clamp before attributing slower ship time to saturation alone. Never improve the benchmark by enlarging the physical time step or discarding acquired evidence.
4. **2G: prove physics remains the same after optimizations.** Run determinism and save/restore replay, reference physics and the new inclined GMAT cases, power/thermal ledger closure, configuration transitions, propulsion/mass coupling, sensor/recorder ordering, frozen forecasts and held-out extension tests. Include half-deployed, damaged, eclipsed and depleted equipment when evaluating geometry/table caches. Cache keys must include every quantity that changes the result; a stale hull or sensor position is not an acceptable speedup.
5. **2D: repeat every screen with representative data.** Room; MISSION, PLAN, MODEL, BLACK BOX, SYSTEMS; FLIGHT; MAP; and the extra SHIP view. Add a committed forecast/uncertainty tube, measured trail, a two-attempt overlay, local MAP region, isolated SHIP system, and a growing multi-attempt archive. The S15 matrix starts fresh and coasts, so empty PLAN/MODEL and charted-universe MAP do not stand in for these populated states. Profile the model worker separately during fit/preview/test, and the main thread during Black Box debrief/compare. Include input latency while that work runs.
6. **2D: validate 3D graphics cost and correctness together.** Record whole-composer draw calls, triangles/lines/points, live geometries, programs and texture sizes. Test out-of-plane rocks, hull/deployment changes, camera orbit/zoom, picking, sensor cones, heading-up/chart-up, clipping and uncertainty tubes in 3D. Recheck buffer reuse against the merged `gfx.ts`; verify positions, dash distances, bounds, changing segment counts and disposal over repeated view/attempt changes. Do not delete small geometry merely because it exists: the baseline has CPU submission/allocation costs as well as GPU work.
7. **2D/integrator: test a real laptop and display density.** Repeat at 1366×768 DPR 1, then 1920×1080 and DPR 2, with actual Intel/integrated hardware and power-saving mode when available. S15's CPU throttle leaves GPU speed unchanged; a high-DPR canvas increases render-target/bloom work. Only adopt a resolution/bloom quality option if its GPU-timed benefit and the legibility of measured/forecast/lattice signals justify it. Check resize, device-pixel-ratio changes and shader compilation on the first visit to each view.
8. **2D/2G: preserve time and alerts.** Hide/show the page, trigger a new caution, resume warp explicitly, fly by hand, recall and lose the ship. Hidden-page hold, alert-to-1×, hands-on 1× and the loss sequence must still work. The top-warp stress harness deliberately reselects warp after alert drops; perform this separate UI acceptance check without that stress policy. Render-on-demand may save graphics work in a settled console view, but must never pause the encounter, recorder or warnings.
9. **Integrator: recheck delivery, not just a bundle warning.** Inventory all output, including the worker and copied public files. Verify cold/warm resource transfers and compression locally. If splitting is adopted, compare actual initial requests/bytes, compilation, interaction acknowledgement and first-open latency for deferred views. Three.js is needed for the initial room; merely moving it into a named vendor chunk does not remove its initial download. Confirm the model worker and any lazy fallback work from relative/sub-path hosting.

[ASSUMED] Suggested gate for owner review: cold interaction-paint median ≤2.5 s under the modest proxy; ordinary 1× p95 ≤33.3 ms in each view; investigate any >100 ms frame. Treat top warp as requested acceleration with an honest achieved-rate/limited indication, not a promise of 2000 ship seconds per wall second. The owner decides these budgets; S15 does not amend `docs/DECISIONS.md`.
