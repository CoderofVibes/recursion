# 1G — Predictive model specification

**Thread:** GPT/Codex · **Branch:** `p1/1g-model-spec` · **Phase:** 1 (parallel)

## Context
Recursion is a browser-based spacecraft engineering roguelike for NASA Space Apps 2026. The ship carries a predictive model that starts from known physics and improves from data the player actually acquires (brief §13). It works like real orbit-determination software: it fits parameters from tracking data. It must never secretly know undiscovered physics, must preserve every forecast as issued, and must show missing or uncertain data honestly (brief §3). Read first:
- `docs/CREATIVE_BRIEF.md`, especially §2, §3, §5, §7 and §13.
- `docs/DECISIONS.md`: P5 (model learns numbers; player supplies rules; **awaiting the owner's answer**), P6 (forecasts, doesn't plan), P7 (measurement realism), P8 (rebuilt from Black Box each recurrence), P11 (truth/belief boundary), P12 (data as a resource).
- `docs/build-plan/README.md` § Conventions.
- Optical navigation references DD05, DD06, DD07 and navigation chapter DD03 (`References/BIBLIOGRAPHY.md`).

## Goal
A specification precise enough that Claude can implement the estimator in Phase 2 (section 2C) and check it against your test cases.

## You own
`docs/model/`, `tests/vectors/estimator/`, `tools/estimator-ref/` (reference generator; Python is fine).

## Specify
1. **Measurement models:** optical tracking fixes (bearing and/or position against known bodies) with noise as a function of sensor power allocation, range, pointing and equipment condition; accelerometers (thrust only); star tracker attitude.
2. **What is estimated:** ship trajectory arcs; parameters such as each body's GM (prior from an arrival calibration at r₀), thruster scale factor and misalignment, sensor biases.
3. **Method:** recommend a method that runs in a browser in real time (e.g. batch weighted least squares / Gauss–Newton over recorded arcs, or an extended Kalman filter with parameter process noise). Justify it; give complexity and timing estimates.
4. **Local confidence:** the model must be confident where data exists and honest elsewhere. Explain how the fitted parameters behave when the structure is wrong (e.g. the GM a Newtonian fit infers drifts as (r₀/r)^0.5 under the inverse-2.5 law).
5. **Model extensions** (P5): fit distance-law exponent; add an unmodeled body (position and GM); region-dependent thrust-response calibration (for Inverse Wells); empirical unmodeled acceleration. For each: what it adds, how it's fitted from all retained data, how a held-out attempt validates it, how a wrong extension visibly fails, and how overfitting is prevented. Add a short section on the alternative if the owner chooses "the model also learns rules by itself" (automatic model selection), so either answer can be built.
6. **Forecast uncertainty:** turning covariance into the forecast envelope (linearized propagation or a small trajectory ensemble), and how it widens beyond sampled regions.
7. **Player-facing diagnostics:** residual time series split into coasting and powered segments; parameter estimate against distance; a confounding indicator (e.g. correlation between engine and gravity parameters when all data comes from burns).
8. **How player decisions feed the model:** route coverage, sensor power and pointing, coast/burn sequencing, equipment damage, Black Box recording rate (P12).
9. **Persistence and versioning:** rebuilding from Black Box records each recurrence (P8); model versions; issued forecasts never change.

## Deliverables
1. `docs/model/estimator-spec.md` with labelled claims (`[ESTABLISHED: source]`, `[ASSUMED]`, `[FICTIONAL]`).
2. `tests/vectors/estimator/*.json`: synthetic scenarios with known truth, generated by `tools/estimator-ref/`, each stating inputs (measurements with sigmas, model structure) and expected recovered parameters with tolerances. At minimum:
   - Newtonian truth, Newtonian model: recovers GM.
   - Inverse-2.5 truth, Newtonian model, data at two distances: fitted GM differs by the expected ratio.
   - Inverse-2.5 truth with the exponent extension: recovers ≈2.5 within stated uncertainty, which narrows with wider distance coverage.
   - Missing second body: direction-dependent residual signature.
   - Burn-only data: engine and gravity parameters strongly correlated (confounded).
3. `tools/estimator-ref/`: runnable reference implementation used to generate the vectors.
