
The default measurement command runs `npm run build`, uses local Vite preview at `127.0.0.1:4175`, and closes its isolated Chrome/server afterwards. It installs nothing and never opens the live deployment. Run benchmarks without concurrent tests/builds. Use a **new run name after changing source**, preserving the pre-merge vectors. See the [runner README](../../tools/studies/s15/README.md) for focused runs and the in-memory patch benchmark.

Passed: production build; **20 load trials, 72 valid frame trials, two separate profile repeats**; 16 focused control/candidate trials; patch dry application; full app/test TypeScript checking with proposed source in memory; **240 line-output/bounds equivalence cases**, including 210 cases of buffer reuse. The measurement matrices had no hidden/paused/wrong-view/wrong-page intervals or uncaught browser exceptions. The production developer handle was absent. Application source/data/root build inputs remained unchanged. The complete application unit suite was not rerun for this documentation/tooling study; the patch is not proposed for immediate application.

What did not pass as a performance claim: the line-buffer patch did not consistently improve browser timings; top warp did not deliver 2000 ship seconds per wall second under the modest profile. A preflight model fault caused an automatic warp drop, and another occurred in a focused patch trial; the study retains that evidence rather than treating the ensuing 1× run as top warp. The initial sandbox could not start Chrome's DevTools endpoint; the authorized runner succeeded outside that sandbox with the same temporary profile and loopback-only server.

## Open questions and uncertainty

- **Owner decision:** adopt this repeatable proxy as a release check, with cold interaction median ≤2.5 s, 1× p95 ≤33.3 ms per view and investigation of frames >100 ms? **Recommend yes**, plus a real integrated-GPU laptop check. These are proposed budgets, not decisions made by S15.
- Highest-p95 profiling did not reproduce the exact earlier 181.7 ms BLACK BOX maximum; supplemental SYSTEMS profiling did not reproduce exactly 333.4 ms either. Both did expose sustained or repeated costs. Host scheduling, caches, JIT, GC and instrumentation affect tails; no exact causal attribution is made for an earlier untraced outlier.
- Fresh/coasting screens do not cover a long archive, populated plan, issued-forecast tube, held-out fit, two-attempt overlay, MAP region or isolated SHIP system. Profile those after 3D. The post-merge list makes this explicit.
- The harness reselects requested top warp after logged alert drops during the bounded sample. It neither suppresses warnings nor proves uninterrupted top-warp gameplay. A separate normal-input acceptance run must preserve A12's automatic drop and hidden-page hold.
