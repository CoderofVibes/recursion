The model had never been near Beta. [ASSUMED] This is 2C's revision 1, where an earned hedge applies everywhere; under revision 2 (A5) it applies inside the validated span (here 500–1,000 km) around every body, and Alpha's pull beyond 1,080 km would carry the default hedge until an outbound flight is held out too.

Without the rule the forecast is honest at first (it ends far short) and then misleading: from about ten hours out it reaches the pass, misses it by 600 km and 10 h, and states a small envelope. ## Open questions and uncertainty

- **Owner: the objective** (proposal in the thread's final message). The build still has the low-orbit band.
- **A rule is never required inside one encounter.** The model's distance table (A4) learns any distance the ship has flown once, and records persist across recurrence. At Alpha a scouting dive substitutes for the rule. The rule pays where there is no table: around Beta, and in later encounters.
- **Owner: the sun** (P14 item 3): 600 W/m², direction 200°.
- **Propellant.** A good low-orbit run spends about 22 m/s and a slingshot about 14 m/s of the 690 m/s main load. RCS is the scarce one: a 180° turn costs 15–29 kg of 300 kg (request 3).
- **Time.** A dive is 30 s at 1000×; a slingshot attempt is 40 h of ship time, about 2.5 min at 1000×. The tick cost caps warp near 2,000× (request 4).
- **Noise replays after recurrence.** The arrival world includes the sensor noise streams, so two identical flights give identical measurements. That keeps replays exact (P2, P9), but the estimator then counts the same evidence twice. Integrator and 2C decide whether noise should differ per attempt.
- **Loss causes.** Power, thermal and propellant exhaustion do not end an attempt yet.
- **Warp near burns.** At 1000× a burn passes in a blink. An automatic slow-down is not built.

## Requests outside my ownership

1. **Integrator / 1C / 2B, camera range noise.** `data/ship-baseline.json` `sensing.camera.rangePriorFraction` is 0.05, applied by 2B as independent noise on every fix (50 km at r₀). It describes doubt about a body's size, which is one shared scale error, not per-fix noise. At that level the model's two-body fit runs away on real flight records: the distance-law test returns exponents of −0.2 or 12. With 1G's 0.2% the same flights give 2.5000 ± 0.0001 and pass. 2F overrides the value for the Gravity range (`rangeShip()` in `src/content/gravity-range/index.ts`). Please change the baseline (or split it into per-fix noise and a size bias) so every encounter gets it.
2. **2C, `src/model/engine.ts` `briefingBodiesAt`:** use the law and body values in force, not `n: 2` and prior μ, for an attempt that has no global fit yet. Today the loop works around it with in-flight refits.
3. **2B → 3A, attitude control:** holding an inertial attitude costs about 12 kg/h of RCS with nothing disturbing the ship (no deadband; minimum-impulse pulses limit-cycle); a 180° turn costs 15–29 kg and peaks at 0.18 rad/s, 18 times the star trackers' limit. Please add an attitude and rate deadband and a slew-rate limit. Until then `burnSteps` releases the attitude after each burn.
4. **2B → 3A / 3C, speed:** `stepShipSystems` takes about 0.23 ms per tick, which caps warp near 2,000×. Mass properties and geometry are recomputed several times a step.
5. **2A / integrator, `src/sim/simulation.ts`:** `Work.store()` rebuilds the world without `sun`, so it is gone after the first `step` or `run`. Add `...(prev.sun ? { sun: prev.sun } : {})`. 2F puts it back each tick meanwhile (`truth-step.ts`).
6. **Integrator, `src/contracts/truth/encounter.ts`:** give `EncounterDefinition` an arrival procedure, an arrival mass and truth-side objective rules, or adopt `EncounterSetup` (`src/game/encounter.ts`).
7. **Integrator, `src/contracts/encounter.ts`:** `Objective` needs a band about a target (`band?: { inner; outer }`); the low orbit is sent as a mid-band `region` circle. Also add the P4 reference radius to `EncounterBriefing`.
8. **Integrator + 2C, attitude convention:** prograde and retrograde mean the believed inertial velocity in the briefing frame (2C's choice, now the game's too). Near a body that moves fast in that frame (Beta, 39.5 m/s) that is not orbital prograde. If it should become body-relative, the forecast and `src/game/belief/resolve.ts` must change together; hosting one resolver in `src/contracts/` or `src/lib/` would guarantee it.
9. **Integrator, `src/contracts/truth/ship.ts`:** a typed field for the camera scene instead of `fieldSignals['ship-environment']` (2B asked too).
10. **Integrator, `docs/DECISIONS.md`:** P16 stays as is. A6: the 220° / 114° estimate is confirmed. Suggested Demonstrated entries: the learning loop with the real model (`src/game/model-loop.test.ts`), the mismatch numbers (`src/content/gravity-range/gravity-range.test.ts`), recurrence resetting the world exactly (`src/game/session.test.ts`).
11. **2D (control room):** `src/app/App.tsx` will mount `ControlRoom` in place of the bench and pass it `snapshot()` each frame plus services. What the loop offers today is `GameControls` (`src/game/belief/controls.ts`): status, pause and warp, `advance`, `preview` and `commit` of a plan, manual `command`, `recall` / `restart`, compare and selection, `rules` (test, adopt, revoke, report), the model port (`state()`, forecasts) and Black Box (`attempt`, `archive`). Tell 2F which of these `ControlRoom` wants under what names and the shell will adapt them. Facts the room should know: the snapshot is in the briefing's inertial frame, so the primary drifts (tens of km over a day); an objective with a `target` has its `region.center` moved to that target's believed position every frame; the compare overlay uses each attempt's believed trail and first forecast; time only runs when the shell calls `advance`, so walking can hold it or not as the owner decides; `burnSteps` (`belief/maneuver.ts`) builds the turn, burn and release commands for one burn.

12. **2C, tracking the second body:** the present state needs range fixes on the primary. After the camera is pointed at Beta for hours the forecast is wrong, then empty (slingshot study). Either build the present state from whichever body is tracked, or report plainly that it is stale.

13. **2C / 1G, the envelope and the bodies' own motion:** before a rule is adopted, the model moves Alpha and Beta about each other under its Newtonian law, and that error is in no uncertainty source. Away from the primary the forecast is then confidently wrong (table above, right-hand column). The hedge should also cover the second body's believed motion, or the forecast should end where that motion matters.
14. **Integrator, `vite.config.ts`:** `server.watch.ignored` contains `**/.worktrees/**`. A dev server started inside a worktree therefore never sees that worktree's own edits and serves stale code until restarted. Ignoring only worktrees *below* the server's root would fix it.
